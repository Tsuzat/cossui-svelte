This guide provides the essentials for adding **coss ui** components to your Svelte application.

## Prerequisites

Our components are built with [Svelte 5](https://svelte.dev), [ShardsUI](https://shardsui.com/) (a Svelte port of Base UI) and [Tailwind CSS v4](https://tailwindcss.com). Before you begin, make sure you have a Svelte or SvelteKit project set up with Tailwind CSS and [shadcn-svelte](https://www.shadcn-svelte.com/docs/installation).

### The `#lib` import alias

Components import each other through `#lib/…`, a [Node.js subpath import](https://nodejs.org/api/packages.html#subpath-imports) for `src/lib`. Add it to your `package.json` once:

```json
{
  "imports": {
    "#lib/*": "./src/lib/*"
  }
}
```

SvelteKit's built-in `$lib` alias points at the same folder, so existing `$lib` imports keep working.

## Adding Components

You can add components **automatically with the CLI** or **manually by copying the files**. Both methods work for primitives, particles, and blocs.

### With the CLI

Each component page provides a command to add it to your project automatically. The CLI will create the necessary files and install any dependencies for you.

```bash
pnpm dlx shadcn-svelte@latest add https://cossui-svelte.com/r/button.json
```

Replace `button` with the name of any component, particle (e.g. `p-button-1`), or hook listed on the site. The registry JSON files are served from `https://cossui-svelte.com/r/`.

See the [Styling](/docs/styling) guide for the theme tokens used by the components.

### Manually

1.  **Find a component** on the [Components](/docs), [Particles](/particles) or [Blocs](/blocs) pages.
2.  **Copy the code** from the **Code** tab.
3.  **Create a new file** in your project (e.g., `#lib/components/ui/button/button.svelte`) and paste the code.
4.  **Install any dependencies** listed on the component's page.
5.  **Import and use** the component in your app.

```svelte
<script lang="ts">
  import { Button } from "#lib/components/ui/button/index.ts";
</script>

<Button>Click me</Button>
```

## Styling

Components are styled with the design token system from upstream **coss ui**, which is defined by CSS variables and implemented with Tailwind CSS.

The variables are the same as shadcn/ui, and are fully customizable. You can modify them in your global stylesheet (e.g., `src/app.css`) to match your design system.

We've introduced a few additional tokens to provide more granular control:

- `--destructive-foreground`: Used for destructive-outline buttons, destructive menu items, badges, and field errors
- `--info` and `--info-foreground`: Commonly used for info-colored badges, toast types, and alerts
- `--success` and `--success-foreground`: Used for success-colored badges, toast types, and alerts
- `--warning` and `--warning-foreground`: Used for warning-colored badges, toast types, and alerts

**Important**: If you manually import components, you must also add these additional tokens to your CSS file (e.g., `src/app.css`). If you use the CLI to add components, check the [Styling](/docs/styling) guide to confirm your theme includes them.

## Fonts

coss components use three CSS custom properties for typography:

- `--font-sans` — Body text, buttons, labels, and most UI elements
- `--font-mono` — Code blocks, `<kbd>`, monospace text
- `--font-heading` — Dialog and AlertDialog titles (`--font-heading: var(--font-sans)` in theme)

By default the theme aliases `--font-heading` to `--font-sans`, so one `--font-sans` variable is enough. You can set a separate `--font-heading` when titles should use a different family — see [Styling — Font Variables](/docs/styling#font-variables).

### Custom fonts

Svelte has no `next/font`, so load fonts with `@font-face` or a package such as [Fontsource](https://fontsource.org), then point the CSS variables at them in your global stylesheet:

```css
@import "@fontsource-variable/inter";
@import "@fontsource-variable/jetbrains-mono";

@theme inline {
  --font-sans: "Inter Variable", sans-serif;
  --font-mono: "JetBrains Mono Variable", monospace;
}
```

For a separate heading font, set `--font-heading` as well:

```css
@theme inline {
  --font-heading: "Inter Variable", sans-serif;
}
```

## Primitive exports

Many components that wrap ShardsUI (Base UI) primitives also re-export the underlying primitive as `<Name>Primitive` (for example Accordion, Popover, Select, Tooltip). Use the styled component when our defaults work, or the primitive when you need different compositions or styling.

```svelte
<script lang="ts">
  import { AccordionPrimitive } from "#lib/components/ui/accordion";
</script>
```

## Migrating from shadcn-svelte or Bits UI

The [Agent Skills](/docs/skills) include migration rules for moving shadcn-svelte and Bits UI code to coss ui, mapping their APIs to the ShardsUI (Base UI) equivalents.

## Working with LLMs

We structure the documentation to make the components **AI-friendly**, so language models can understand, reason about, and modify them. To support this, we include:

- **[Agent Skills](/docs/skills)** — Install coss knowledge directly into your AI assistant. Covers primitives, styling conventions, migration patterns, and particle examples.
- A `llms.txt` file that provides a map of the documentation and component structure for your AI agent.
- A **Copy Markdown** button on every page, so you can easily share content or feed it to your AI workflows.
